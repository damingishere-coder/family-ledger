# 历史数据导入格式

选择文件后，FamilyLedger 会先进行只读解析并显示来源工作表、布局、日期、有效行数、来源汇总、计算汇总和警告。此时不会写入数据库；只有点击“确认导入”才会创建成员、账户、快照和导入记录。预览状态分为“可导入、自然月重复、已阻止、已忽略”，确认时只处理可导入项。

所有来源日期都会保留在导入审计信息中，快照日期统一保存为该自然月月末。同一个自然月最多存在一个已完成快照；文件名或来源日期不同也不会重复写入。

## CSV / Excel

支持 `.csv`、`.xlsx` 和 `.xlsm`，不支持旧版 `.xls`。CSV 可以使用 UTF-8（含 BOM）或中文 Windows 常见的 GB18030 编码；单个文件不能超过 20MB。

CSV 与普通明细 Excel 的第一行必须是表头。列名支持中文或英文，最小示例：

| 盘点日期 | 家庭成员 | 账户名称 | 账户类型 | 金额 |
|---|---|---|---|---:|
| 2026-08-31 | 大明 | 微信 | wallet | 987.63 |
| 2026-08-31 | 大明 | 招商银行信用卡 | credit_card | -18.52 |

可选列：机构名称、信用额度、还款日、是否计入家庭净资产。

账户类型必须使用以下稳定值之一；中文描述仍可作为辅助文字，但建议使用英文枚举：

- `wallet`
- `debit_card`
- `credit_card`
- `investment`
- `receivable`
- `other_asset`
- `other_liability`

系统也能识别旧版“每月一个工作表”的家庭月度矩阵。每个工作表独立解析；重复辅助页“工作表1”会标记为忽略。工作表月份和日期单元格冲突、同一快照重复账户、账户匹配不唯一，或公式没有可用缓存值时，该工作表会被阻止。

空白金额会导入为 `NULL`，不会变成零；零和负数保持原值。银行账户按“机构 + 储蓄卡/信用卡”标准化，账户匹配同时考虑成员、类型、名称和机构。

## Markdown

支持 `.md`、`.markdown` 和 `.txt`，文本编码可以是 UTF-8（含 BOM）或 GB18030。日期标题需包含类似 `## 2025年12月25日` 的内容，并在成员“明细”标题下列出账户和金额。横向“微信 / 支付宝”表格按表头与下一行一一对应；储蓄卡读取银行和余额，信用卡读取银行、额度、待还金额与还款日。小记、总计、家庭总余额等汇总行不会创建账户。

成员别名“大明同学 / 贤贤宝贝”会标准化为“峰峰 / 贤贤”，“自信银行”会校正为“中信银行”。共享投资、待收欠款和其他负债归“家庭公共”；明确标注“不计入总数”的待收欠款仍会保留，但不参与净资产计算。内部类型仍为 `receivable`，界面显示为“待收欠款”。

无法识别的文件、损坏的工作簿和完全没有有效明细的内容会停留在预览窗口并显示原因，不会静默写入部分空数据。
