# 历史数据导入格式

在“数据管理 → 导入并核对历史表格”中一起选择有关联的 Excel 和 Markdown 文件。文件只在本机解析，预览不写数据库。先确认账户归属及收付款方向，再选择月份并保存；写入前自动备份。单次最多 5 个文件，每个 20MB，合计 40MB。

同月 Excel 明细提供金额；Markdown 用于日期、还款日、明确的归属及“不计入总数”标记，金额不一致会并排列出。跨文件匹配不唯一、日期冲突、无缓存公式及重复主来源月份都不能写入。原表明确写在谁的明细下就归谁，没有标注的项目必须选择成员；“其他”也可以作为所属分组。仅写“借款／待还款”时需要确认是别人欠我们还是我们欠别人。

预览逐项显示原文件位置、原值、旧记录和新记录。月份状态包括新增、可修正、无变化、待确认、保留原记录、来源待核对和辅助页忽略。只有新增或可修正的月份允许保存；一个月份中仍有冲突时，整个该月份保留。可单独选择其他无冲突月份。

修正仅更新有可信导入基线的条目，不删除或重建月份，不覆盖手工盘点或可能已手改的记录。旧版数据缺少逐项基线时，只有来源哈希与旧修复记录一致、全部受改字段与来源一致且无手改迹象的条目可修正。之后的导入会保存逐项基线、来源位置和已确认的映射，随完整 JSON 备份导出。

预览有效期为 30 分钟，服务重启后需重新选择文件；最多保留最近 8 个预览。账户选择改变后必须重新核对，数据库自预览后发生变化也会拒绝写入。重复提交同一确认返回原结果，不会再次导入。

所有来源日期都会保留在导入审计信息中，快照日期统一保存为该自然月月末。同一个自然月最多存在一个已完成快照；文件名或来源日期不同也不会重复写入。

## CSV / Excel

支持 `.csv`、`.xlsx` 和 `.xlsm`，不支持旧版 `.xls`。CSV 可以使用 UTF-8（含 BOM）或中文 Windows 常见的 GB18030 编码；单个文件不能超过 20MB。

CSV 与普通明细 Excel 的第一行必须是表头。列名支持中文或英文，最小示例：

| 盘点日期 | 家庭成员 | 账户名称 | 账户类型 | 金额 |
|---|---|---|---|---:|
| 2026-08-31 | 大明 | 微信 | wallet | 987.63 |
| 2026-08-31 | 大明 | 招商银行信用卡 | credit_card | -18.52 |

可选列：机构名称、信用额度、还款日、是否计入家庭净资产。

账户类型必须使用以下稳定值之一；中文描述仍可作为辅助文字，但建议使用英文枚举：

- `wallet`
- `debit_card`
- `credit_card`
- `investment`
- `receivable`
- `other_asset`
- `other_liability`

系统也能识别旧版“每月一个工作表”的家庭月度矩阵。每个工作表独立解析；重复辅助页“工作表1”会标记为忽略。工作表月份和日期单元格冲突、同一快照重复账户、账户匹配不唯一，或公式没有可用缓存值时，该工作表会被阻止。

空白金额会导入为 `NULL`，不会变成零；零和负数保持原值。银行账户按“机构 + 储蓄卡/信用卡”标准化，账户匹配同时考虑成员、类型、名称和机构。

## Markdown

支持 `.md`、`.markdown` 和 `.txt`，文本编码可以是 UTF-8（含 BOM）或 GB18030。日期标题需包含类似 `## 2025年12月25日` 的内容，并在成员“明细”标题下列出账户和金额。横向“微信 / 支付宝”表格按表头与下一行一一对应；储蓄卡读取银行和余额，信用卡读取银行、额度、待还金额与还款日。小记、总计、家庭总余额等汇总行不会创建账户。

成员别名“大明同学 / 贤贤宝贝”会标准化为“峰峰 / 贤贤”，“自信银行”会校正为“中信银行”。投资、待收欠款及其他负债不会按类型自动归入“家庭公共”。明确标注“不计入总数”的待收欠款仍会保留，但不参与净资产计算。内部类型仍为 `receivable`，界面显示为“待收欠款”。

无法识别的文件、损坏的工作簿和完全没有有效明细的内容会停留在预览窗口并显示原因，不会静默写入部分空数据。

## 接口与只读检查

- `POST /api/import/batch/preview`：上传多个 `files`，返回来源、账户组、逐月差异、预览 token 和 review_id。
- `POST /api/import/batch/review`：传入 token 与 mappings（账户组 key 对应 member_name、account_type），重新生成核对结果。
- `POST /api/import/batch/confirm`：传入 token、最新 review_id 和选中的 months；备份后在单事务中保存。
- 旧的四个单文件接口保留，使用相同来源解析规则；需要归属或方向确认的文件必须使用联合核对流程，不能通过旧接口绕过。
- `scripts/review_import_sources.py --database <数据库> --files <文件...> [--mappings <映射JSON>] [--output <报告JSON>]` 使用 SQLite `mode=ro`，只读检查不会启动服务或修改数据库。该脚本与网页使用同一解析及核对服务。
- 旧 `repair_imported_history.py` 是一次性的历史重建工具，不用于新的归属修正；不要清除其已执行标记或重复强制重建。
