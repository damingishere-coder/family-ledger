# 历史导入修复执行任务

## 背景

现有 Markdown 导入器按单行首列/末个数字猜测字段，导致横向表格错位；旧版多工作表家庭月度 Excel 也不符合当前扁平表头格式。数据库中已经存在由错误解析产生的历史快照、成员和账户。

## 目标

- 按表格语义解析横向 Markdown 和旧版家庭月度 Excel。
- 所有导入快照按自然月月末存储，并按已完成快照的自然月去重。
- 扩展预览结果，明确可导入、重复、阻止和忽略项。
- 提供默认只读的历史修复命令：先生成来源哈希和修复报告，应用时先备份并在单事务中重建历史数据。
- 将 `receivable` 的界面名称调整为“待收欠款”，账户列表按成员和账户类型两级展示。

## 允许修改范围

- `backend/app/importers/`
- `backend/app/services/imports.py`
- `backend/app/services/backups.py`（仅备份文件名防碰撞）
- `backend/app/models.py`（仅已完成快照的自然月唯一索引）
- `backend/app/api/data.py`
- `backend/tests/`
- `frontend/src/`
- `scripts/repair_imported_history.py`
- `docs/import-format.md`

## 禁止修改范围

- 三个私人附件及其内容不得加入 Git。
- 未确认前不得修改正式数据库或重启 8767 服务。
- 不改变现有四个导入接口路径，不增加绕过预览的替换接口。
- 不重置、清理或覆盖用户已有的 `backups/` 内容。

## 已确定实现要求

- 成员和机构标准化：大明同学映射峰峰，贤贤宝贝映射贤贤，自信银行映射中信银行。
- 银行账户以“机构 + 储蓄卡/信用卡”命名，匹配同时考虑成员、类型和机构。
- 家庭公共承接共享投资、待收欠款和待还姑姑；明确不计入总数的条目保留排除标记。
- Excel 账户明细为金额依据；Markdown 仅校正来源日期、信用卡还款日并核对汇总。
- 公式无缓存值、来源月份冲突或无法解释的数据冲突必须阻止写入。
- 空白为 `NULL`，零与负数保持原值；汇总行不生成账户。

## 验收标准

- 横向 Markdown 不再生成纯数字、小记、家庭总余额或“11号”等账户。
- 多工作表 Excel 独立预览，并显示 `layout`、`source_sheet`、`status`、`blocking_errors`、来源汇总和计算汇总。
- 同一自然月最多一个已完成快照；重复执行不会重复写入。
- 临时数据库修复验证得到 20 个重建月份和 1 个保留手工月份，成员仅峰峰、贤贤、家庭公共。
- 失败路径回滚，SQLite 完整性与外键检查通过。

## 测试命令

- `python -m pytest backend/tests`
- `npm test -- --run`（工作目录 `frontend`）
- `npm run typecheck`（工作目录 `frontend`）
- `npm run build`（工作目录 `frontend`）
- 修复脚本默认只读预演；仅在用户再次确认后使用 `--apply` 指向正式数据库。

## 返回格式

报告代码改动、只读预演、备份/事务验证、测试结果、Git 提交与 PR/CI 状态；正式数据库是否已修改和服务是否已重启必须单独明确说明。
